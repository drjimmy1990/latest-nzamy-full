## ٢ · ما في الترحيل

| القسم | المحتوى |
|---|---|
| `lawyer_clients` | المالك + المكتب + `client_user_id` (اختياري، لحساب حقيقي) · `client_type` · الاسم/الجوال/البريد/المدينة · فرد: `national_id_hash` (hex 64) + `power_of_attorney_no` · شركة: `commercial_register_no` + `tax_number` + `unified_number_700` · `flags` (vip/new/loyal/urgent/corporate/inactive فقط) · `rating` ١–٥ · `fee_total_sar`/`fee_paid_sar` (NULL ≠ صفر؛ مقدَّم بلا إجمالي مرفوض) · `first_engagement_on` · `status` |
| فرادة | `(firm_id, national_id_hash)` و`(owner_user_id, national_id_hash)` حين لا مكتب — فهارس جزئية؛ ومثلهما للسجل التجاري |
| `lawyer_client_notes` | `private` (الكاتب فقط) / `firm` (زملاؤه النشطون)؛ الموكّل لا يقرأها أبداً؛ لا تُكتب إلا على بطاقة يقرؤها الكاتب |
| `service_requests` | عمودان اختياريان: `lawyer_client_id`، `firm_id` + سياسة قراءة لأعضاء المكتب النشطين (`can_access_case_row(null, firm_id)`) |
| العضوية | فهرس فريد `(firm_id, user_id)` · trigger `ensure_firm_owner_membership` (security definer لأنه يعمل داخل `handle_new_user` بلا `auth.uid()`) · backfill |
| إصلاح التكرار | `is_active_firm_member` + الثلاثة الشقيقة (محروسة بـ`to_regclass`)؛ إسقاط السياسات الأربع وإعادتها على الدوال |
| البند ١٧٠ | ٦ سياسات (`insert`/`update` × ٣ جداول) |

**لا `DROP`، لا `TRUNCATE`، لا `DELETE`.** لا نقل بيانات (§١٧ خطوة ٣).

## ٤ · ما لم يُفعل هنا عمداً

- **لا كود شاشات في هذا الالتزام** — الخطوة ٢ من التسلسل، التزام منفصل. ترتيب النشر: **تشغيل الترحيل أولاً**، ثم نشر ذلك الكود.
- مسارات المرحلة ١ ما زالت تبتلع خطأ قراءة `firm_members` (`const { data: membership } = …`) — بعد الإصلاح لن يحدث الخطأ، لكن الابتلاع نفسه يُعالَج في الخطوة ٢ (تسجيل الخطأ على الأقل).
- الدعوة عبر البريد (`team_invitations` موجود منذ ٢٠٢٦٠٦٠٣ ولا يستخدمه أحد) — الخطوة ٢ تبدأ بـ«إضافة عضو موجود بحسابه»، والدعوات لاحقاً.
- `business/cases/new` (فحص تعارض وهمي بـ`setTimeout`، البند ١٩٣ الثاني) — الصفحة مخفيّة بقرار ٢٠٢٦-٠٨-٢٦؛ يُربط بالفحص الحقيقي في الخطوة ٢ أو يُزال معها.
