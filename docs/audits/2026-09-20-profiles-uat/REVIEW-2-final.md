## MUST FIX before delivery

1. **`src/app/api/v1/business/members/route.ts:341` — the invite lookup takes a LIKE *pattern*, not an e-mail, so a corporate owner can enumerate other accounts' names and e-mail addresses.**
   `.ilike("email", email.trim())` passes the caller's raw string to PostgREST, where `%`, `_` and `*` are wildcards. The route's own header calls this "A CLOSED KEY SET … one e-mail" (`:67-71`) — the code does not enforce that. An authenticated corporate **owner** POSTing `{"email":"ahmed%@%","role":"employee"}` matches one eligible `profiles` row and gets **201** with that person's `display_name` and `email` in the body (`:388-397`), plus an active `business_members` row granting that account access to the company; a pattern matching two rows fails `.maybeSingle()` → 500, and a pattern matching none → 404, so the three answers are a working oracle. This defeats part of what `20260921_01` (UAT-SEC-001) exists to protect — `profiles` rows other than your own — through a route that shipped in this range. The same line exists at `src/app/api/v1/firm/members/route.ts:206` (pre-existing, same defect, now mirrored).
   *Fix* — escape the LIKE metacharacters before the lookup, in both routes:
   ```ts
   // PostgREST maps `*` → `%` and hands the rest to SQL ILIKE, where `%` and
   // `_` are wildcards. An e-mail is a literal, so neutralise all of them.
   const emailPattern = email.trim().replace(/[\\%_*]/g, (c) => `\\${c}`);
   const { data: account, error: accountError } = await service
     .from("profiles")
     .select("id, display_name, email, user_type")
     .ilike("email", emailPattern)
     .in("user_type", [...INVITABLE_ACCOUNT_TYPES])
     .maybeSingle();
   ```
   (Equivalently, drop `ilike` for an exact match — `auth.users` lowercases addresses and `handle_new_user` copies `new.email` verbatim, so `.eq("email", email.trim().toLowerCase())` is correct in practice.) Then extend `route.test.ts`'s "the invite lookup is one e-mail" case with an assertion that a `%`/`_`/`*` in the input cannot reach the query.
