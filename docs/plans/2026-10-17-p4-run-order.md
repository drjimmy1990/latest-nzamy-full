## 20261017_41_notes_visibility_case_team.sql (owner ١٦٩)

**What it does:**
- Adds `public.case_team_members` and the SQL definition of a case team (`public.case_team_user_ids`): the lead, the filer and the added members, each only while an active member of the case's firm. The client is never on the team.
- Adds `case_team` as a third scope on `case_notes`.
- Pins each note's scope in RLS on `case_notes`, `lawyer_client_notes` and `consultation_notes`.
- Drops the platform-admin read of private notes.
- Revokes every guest privilege on the four tables and on the seven new functions.

**Prerequisites:** 20260903_phase2, 20260905_phase3 and 20260910_case_notes, all live already. The file raises if any is missing.

**Order relative to the code:** either order works.
- **Code before SQL:** `GET /api/v1/cases/[id]/team` answers 503, the case page greys out «فريق القضية» with the reason, and private and firm notes behave as today.
- **SQL before code:** the old code never sends `case_team`. Its client-notes POST may still stamp `firm_id` on a private note, and the new rule accepts that.
- **Recommended:** SQL first, then deploy.
