# مسودة عقد `POST /api/v1/ext/cases/sync` · 2026-11-21

> الحالة: **مسودة مواصفات فقط، غير مطبّقة ولا معتمدة.** تعتمد على قرارات المالك المفتوحة في [خطة إضافة كروم](2026-11-21-chrome-extension-integration.md) §٥. جداول `case_dossiers` / `case_dossier_items` **غير موجودة** في المستودع الرئيسي (موجودة كمسودة في فرع MCP فقط)، فالحقول أدناه اقتراح يُراجَع مع تلك المسودة قبل التنفيذ.

## الغرض
مسار واحد يحلّ محل المسارات الثلاثة التخمينية (`workspace/import-archive`، `gov-sync/batches`، `najiz/sync`) التي لا وجود لها في الخادم، فيصبح لكل سحبة ردّ صريح يميّز النجاح من الغياب.

## المصادقة
- `Authorization: Bearer <PAT|OAuth>` عبر `_extAuth.ts` نفسها المستخدمة في `/ext/ai/runs` (الوورد وMCP).
- لا RLS مع التوكن: كل استعلام يُقيَّد يدويًا بـ`user_id` المستخلص من التوكن، ولا يُقبل `user_id` من الجسم أبدًا.
- بدون توكن → `401`. نطاق التوكن غير كافٍ → `403` (نطاق مقترح: `cases:sync`).

## الطلب
```json
{
  "idempotency_key": "string (≤128)، مطلوب، يُولَّد من الإضافة لكل سحبة",
  "source": { "platform": "najiz|taradhi|enforcement|khebra|infath|ifa", "captured_at": "ISO-8601", "extension_version": "1.2.0" },
  "case": {
    "number": "string، مطلوب",
    "year_hijri": "string?",
    "court": "string?",
    "type": "string?",
    "status": "string?"
  },
  "parties": [{ "role": "plaintiff|defendant|other", "name": "string", "id_masked": "string?" }],
  "sessions": [{ "date": "ISO-8601", "kind": "string?", "outcome": "string?", "notes": "string?" }],
  "attachments": [{ "kind": "string", "title": "string", "sha256": "hex", "size": 0, "mime": "string", "url": "string? (رابط داخل البوابة، للمرجع فقط)" }],
  "records": [{ "kind": "enforcement_seizure|ruling|memo|other", "text": "string", "sha256": "hex" }]
}
```
- `attachments` تُرسل **بصماتها وبياناتها الوصفية فقط**؛ رفع الملف نفسه خطوة منفصلة (خارج هذا العقد) إن تقرر.
- الحد الأقصى للجسم: ١ م.ب؛ ٢٠٠ عنصر لكل مصفوفة. يتجاوز → `413`.
- `id_masked`: الإضافة تقنّع الهويات قبل الإرسال (آخر ٤ أرقام فقط) — قرار مقترح يحتاج موافقة.

## المعالجة
1. التحقق من المخطط؛ فشل → `422` مع `errors[]` بالمسار والسبب.
2. البحث عن `(user_id, idempotency_key)`: إن وُجد → `200` بنفس الردّ السابق دون كتابة ثانية.
3. مطابقة القضية بـ`(user_id, platform, number)`: تُنشأ إن لم توجد، وتُحدَّث الحقول الفارغة فقط (لا تُستبدل قيم عدّلها المحامي يدويًا).
4. إلحاق الأطراف/الجلسات/المرفقات/السجلات بالقضية، مع إزالة التكرار بـ`sha256` للعناصر ذات البصمة.
5. (لاحقًا، بعد اعتماد جداول الملف) كتابة عناصر في `case_dossier_items` بـ`kind` و`hash`.
6. الكتابة كلها في معاملة واحدة: إما كل شيء أو لا شيء.

## الردود
| الكود | المعنى | جسم الردّ |
|---|---|---|
| `201` | قضية جديدة أُنشئت | `{ "case_id", "created": true, "counts": {parties, sessions, attachments, records} }` |
| `200` | قضية موجودة حُدِّثت، أو تكرار لنفس `idempotency_key` | نفس الشكل مع `"created": false` و`"replayed": bool` |
| `401/403` | مصادقة/نطاق | `{ "error": "code" }` |
| `413/422` | حجم/مخطط | `{ "error": "code", "errors": [...] }` |
| `429` | حد المعدل | `Retry-After` |
| `5xx` | خطأ خادم | تُعاد المحاولة |

**قاعدة الإضافة:** تُحذف السحبة من الطابور عند `200/201` فقط، وتُعاد عند `429/5xx/شبكة` بتراجع أسّي، وتُوسَم «مرفوضة» (لا تُعاد تلقائيًا) عند `401/403/413/422`. **لا يُعامَل `404` كحالة عادية بعد اليوم.**

## السرية
- لا يُسجَّل نص الحزمة في سجل النشاط؛ بصمات وأعداد فقط.
- الطابور المحلي في `chrome.storage.local` يحتاج قرارًا: تشفير أو مدة انتهاء (مثلاً ٧ أيام).

## أسئلة مفتوحة
1. هل المسارات القديمة منشورة على الإنتاج؟ إن نعم يُبقى عليها مؤقتًا كطبقة توافق.
2. اسم النطاق `cases:sync` ومدة صلاحية PAT.
3. رفع الملفات المرفقة: داخل هذا المسار أم مسار منفصل؟
4. تقنيع الهويات في الإضافة أم في الخادم؟
