### ملخص الهيكل

| القسم الرئيسي | الأقسام الفرعية | العمق | المحلل (parser) |
|--------------|----------------|-------|----------------|
| أنظمة ولوائح | 30 قسم (إجرائي، جنائي، إداري...) | 4 مستويات | `parse-laws` |
| أوامر وتعاميم | حسب الجهة المصدرة | 3-4 مستويات | `parse-decrees` |
| مبادئ وسوابق قضائية | سوابق + مبادئ (عادي/إداري/لجان) | 4-5 مستويات | `parse-precedents` |
| فقه ومراجع | 15 كتاب (شرعي + قانوني) | 3 مستويات | `parse-feqh` |

> ⚠️ **مهم:** المحلل (parser) يبحث تلقائياً في كل المجلدات الفرعية بشكل متكرر (recursive). لا تحتاج أن تشير لكل مجلد فرعي — فقط أشر للمجلد الرئيسي.

### كل ملف `.md` يحتوي طبقتين

```markdown
---
type: law                    ← ↕ طبقة الآلة (frontmatter)
slug: labor-law              ←   يقرأها البرنامج تلقائياً
title: نظام العمل            ←
category: أنظمة              ←
---
                             ← ↕ طبقة القارئ (visible card)
# نظام العمل                ←   يراها المستخدم في الموقع
...محتوى النظام...           ←
```

## 3. خطوات البذرة الكاملة (Full Seed)

افتح Terminal في مجلد المشروع (`nzamy-website/`) ونفّذ:

### الخطوة ١ — تحقق من الوضع الحالي
```bash
npm run library:status
```
يعرض عدد الصفوف في كل جدول.

### الخطوة ٢ — امسح البيانات القديمة
```bash
# أولاً: شوف ماذا سيُحذف (المعاينة هي الوضع الافتراضي — بدون حذف)
npm run library:clear

# إذا كل شيء صحيح، امسح فعلياً (وعلى الإنتاج أضف --force-prod)
npm run library:clear -- --live
```

### الخطوة ٣ — حلّل ملفات المحتوى
```bash
npm run library:parse -- --input "D:/المسار/إلى/المكتبة_القانونية"
```
> المحلل يبحث تلقائياً عن المجلدات العربية الأربعة (`أنظمة ولوائح`، `أوامر وتعاميم`، ...) ويعالج كل ملفات `.md` داخلها بشكل متكرر.

ينتج ملفات JSON في مجلد `library-toolkit/output/`

### الخطوة ٤ — ازرع في قاعدة البيانات
```bash
# أولاً: تجربة جافة (بدون كتابة فعلية)
npm run library:seed -- --dry-run

# إذا كل شيء صحيح، ازرع فعلياً
npm run library:seed
```

### الخطوة ٥ — تحقق من النتائج
```bash
npm run library:status
npm run library:verify
```

## 4. أمر واحد يفعل كل شيء (Reseed)

```bash
# أعد البذرة كاملة: parse → زرع → تحقق (يمرّر --input تلقائياً إلى خطوة parse)
npm run library:reseed -- --input "D:/المسار/إلى/المكتبة_القانونية"

# نسخة مع مسح حي أولاً (مدمِّرة — على الإنتاج أضف --force-prod)
npm run library:reseed:wipe -- --input "D:/المسار/إلى/المكتبة_القانونية"
```

## 5. تحديث قسم واحد فقط

```bash
# مثال: تحديث الأنظمة فقط
npm run library:clear -- --live --type laws
npm run library:parse -- --input "D:/المسار" --type laws
npm run library:seed -- --type laws
```

الأقسام المتاحة: `laws` | `decrees` | `precedents` | `feqh`

## 6. جدول مرجعي سريع

| الأمر | ماذا يفعل | متى تستخدمه |
|-------|-----------|-------------|
| `npm run library:status` | عدد الصفوف | تحقق سريع |
| `npm run library:clear` | معاينة المسح (DRY افتراضياً) | فحص قبل المسح |
| `npm run library:clear -- --live` | مسح الكل فعلياً | قبل إعادة البذرة |
| `npm run library:clear -- --live --type laws` | مسح قسم واحد فعلياً | تحديث جزئي |
| `npm run library:parse -- --input "مسار"` | تحليل → JSON | بعد تعديل المحتوى |
| `npm run library:parse -- --input "مسار" --type feqh` | تحليل قسم واحد | تحديث جزئي |
| `npm run library:seed` | زرع في DB | بعد التحليل |
| `npm run library:seed -- --dry-run` | زرع تجريبي | فحص قبل الزرع |
| `npm run library:verify` | فحص صحة | بعد الزرع |
| `npm run library:reseed -- --input "مسار"` | parse + زرع + فحص | إعادة كاملة |

## 8. حل المشاكل الشائعة

| المشكلة | الحل |
|---------|------|
| `Missing SUPABASE_URL` | تأكد من ملف `.env.local` |
| `Missing SUPABASE_SERVICE_ROLE_KEY` | نفس الشيء ↑ |
| `FK constraint violation` | شغّل `library:clear` قبل `library:seed` |
| عدد الصفوف = 0 بعد البذرة | تحقق أن المجلد يحتوي مجلدات عربية (`أنظمة ولوائح` الخ) |
| `Parser error` | تأكد أن الملفات بترميز UTF-8 |
| ملف كبير جداً (> 1MB) | طبيعي — بعض المبادئ القضائية ملفات ضخمة |
