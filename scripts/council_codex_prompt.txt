أنت الآن عضو مجلس المراجعة التشاوري الثلاثي (Codex CLI / GPT-5.6-Luna) في مشروع منصة "نظامي" القانونية الذكية (Saudi Legal-Tech).
ملاحظة إلزامية: لا تشغل أي أوامر CLI ولا تحاول فتح متصفح أو تشغيل أدوات خارجية إطلاقاً. قدم تحليلك ونقدك مباشرة كنص Markdown متكامل في مخرجك النهائي.

مطلوب منك تقديم نقد وتحليل معماري وتجاري ونظامي مستقل وحاسم (دون مجاملة) للمسائل الاستراتيجية التالية وفق معايير السوق السعودي والأنظمة المعمول بها:

1. هيكلة باقات العميل (Client Package Architecture):
   - مقترح المالك: توحيد مفهوم "الحماية القانونية / التأمين القانوني" وإلغاء التشتت واعتماد 3 خيارات فقط كحد أقصى:
     أ) الدفع بالعمل القانوني (Pay-as-you-go / Pay-per-piece): بدون اشتراك، ادفع فقط عند طلب مذكرة، عقد، أو استشارة.
     ب) التأمين القانوني الفردي (Individual Legal Protection): السعر الأساسي 365 ر.س/سنة (ريال يومياً)، وعرض يوم التأسيس بأقل من ريال يومياً (مثلاً 222 أو 296 ر.س/سنة).
     ج) التأمين القانوني الجماعي (Group Legal Protection / نمط "الرَّبع"): مدرج (Tiered) - كلما زاد عدد الأعضاء (مثلاً 3-10) قلت التكلفة للفرد وزادت المزايا (5 استشارات مرئية سنوياً لكل فرد، خصم أعلى على الترافع)، مع آلية الضامن المالي (Payment Guarantor) حيث يلتزم مالك المجموعة بسداد سنوي أو ربع سنوي عن كامل المجموعة، مع إمكانية الترقية السلسة من الفردي للجماعي.
   - ما رأيك المعماري والتجاري؟ كيف تنفذ هندسياً ومالياً وقانونياً في بيئة Supabase + Stripe/Moyasar؟

2. تدقيق أدوار المستخدمين السبعة وتنقيح الصفحات الشبحية (Ghost Pages Purge):
   - الأدوار: الشركات (corporate/business)، المنشآت المصغرة (micro)، القطاع غير الربحي (ngo)، مكاتب المحاماة (firm)، مقدمو العدالة (provider: notary, arbitrator, bailiff)، الجهات الحكومية (government)، وإدارة المنصة (admin).
   - ما هي الصفحات الشبحية والـ Junk والبيانات الوهمية (مثل celebrities في الأدمن ومطبوعات بدون ربط) التي يجب حذفها أو تنظيفها فوراً؟

3. معالجة حالة الحافة الحرجة: مستخدم يطلب خدمة ورصيده صفر / ليس لديه اشتراك:
   - حالياً الـ API يرجع 402 أو يسجل stub بدون دفع حقيقي أو يعلق الطلب.
   - ما هو الـ UX Flow والـ State Machine الأمثل للمستخدم غير المشترك أو بدون رصيد عند طلب خدمة؟

4. مراقبة استهلاك الموارد والتوكنز في لوحة الأدمن (Admin Resource & Token Monitoring):
   - صفحة /dashboard/admin/ai-usage حالياً تستخدم بيانات وهمية (Mock array). كيف نبني نظام تيليمتري حقيقي وتتبع توكنز وتكاليف لكل Tenant وشركة ومحامٍ؟

5. خزنة المحامي والمطبوعات المخصصة (Lawyer Vault & Custom Branded Letterheads):
   - صفحة /ai/vault غير مربوطة في سايدبار المحامي وتحتوي بيانات وهمية، ولا توجد مطبوعات خاصة بالمحامي الفرد. كيف تُصمم الخزنة وتصدير المذكرات بترويسة المحامي وختمه؟

6. الورك فلو الشامل للسوق المهني (Marketplace Workflows):
   - صفحة /marketplace و /dashboard/lawyer/marketplace مغلقة حالياً تحت لافتة "قريباً" بسبب الموك في MyMarketplaceDashboard.
   - كيف يُصمم سير العمل المهني لتعاقد محامٍ مع محامٍ آخر، وطلب العميل لمحامٍ بعينه مقابل طرح طلب في السوق المفتوح؟

7. المقارنة المعيارية التنافسية (Competitive Benchmark):
   - مقارنة نظامي مع قادة السوق السعودي (ناجز، شورى Shura، إياس Eyas، محامي دوت كوم) والمنصات العالمية (Clio، LegalZoom).
   - أين تتفوق نظامي وما هي الثغرات الحرجة التي يجب سدها؟
